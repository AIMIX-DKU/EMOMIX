샘플 동작을 서버 API 기반 화면으로 대체했다. 작업 중복 제출을 막고, 금전/생성 요청은 동일 요청 재시도에 동일 멱등키를 사용한다. 템플릿 열람과 다운로드는 접근 기록 및 환불 조건에 영향을 줄 수 있음을 안내한다. 관리자 기능은 서버의 ADMIN 권한이 필요하다.

## 검증 완료

- `node --test api.test.js`: 5개 통과. 쿠키/최신 CSRF, 동시 401의 공유 refresh, 연결 실패 후 변경 요청 자동 재전송 방지, 스토리지 PUT 후 complete 순서를 확인.
- Vite 프로덕션 빌드 성공.
- Playwright와 모의 서버: 53개 화면 변형, 100개 API 작업 관찰. 실제 OpenAPI의 경로·메서드·필수 필드·타입·열거형 및 CSRF/멱등키 검증. 주요 생성/편집·커뮤니티·상품·관리자 동작, 결제 승인/구독 시작/카드 변경 콜백, 권한 제한과 360px 화면 확인.
- 실제 배포 백엔드: 제공된 테스트 계정 로그인 및 주문/지갑 API 확인. 일반 결제는 실제 토스 테스트 위젯과 테스트 인증을 거쳐 성공 콜백까지 복귀.
- 실제 구독 카드 등록창이 별도 개별 연동용 공개 키로 열리는 것을 확인. 카드번호/주민번호 입력과 실제 구독 청구는 수행하지 않음.

모의 테스트는 외부 GPU·카드사·판매자 정산의 실거래 성공을 증명하지 않는다. 테스트 계정 비밀번호와 클라이언트 키 값은 저장소에 포함하지 않는다.

## 백엔드/운영 환경에서 해결·확인할 사항

1. **일반 결제 최종 승인 차단**: 실제 `/payments/confirm`이 HTTP 402와 토스 API 키의 IP 접근 정책 거절 오류를 반환했다. 토스 테스트 인증은 통과했지만 승인/크레딧 지급은 성공하지 않았다. 백엔드 담당자가 토스 시크릿 키의 접근 정책과 배포 서버 허용 IP를 확인해야 한다. 프론트는 오류를 표시하고 완료로 처리하지 않는다.
2. 프론트 배포 프로젝트에 `.env.example`의 공개 키 환경변수를 설정하고 재배포해야 한다. 서버 키와 같은 상점/환경인지 확인한다. GPU 워커 키는 서버에서만 사용한다.
3. 위 정책 해결 후 실제 테스트 결제 승인→잔액 반영→환불, 구독 카드 인증→첫 청구→카드 변경/해지/재개를 통합 검증한다. 카드 등록창 표시와 모의 콜백 테스트만으로 정기 결제 검증 완료를 주장하지 않는다.
4. GPU 생성/인페인팅·내보내기 결과, Discord OAuth 공급자 설정, 창작자 정산과 관리자 처리는 각 권한 및 외부 서비스 환경에서 최종 검증이 필요하다.

## 실제 배포 환경 추가 점검

2026-11-25 테스트 계정으로 다음을 추가 검증했다.

- 실제 응답으로 23개 프론트 화면을 확인. 브라우저 JavaScript 오류와 360px 가로 넘침 없음. 관리자 화면은 일반 계정의 접근 제한을 확인했고, 권한 안내를 403으로 명확하게 표시하도록 수정.
- 이미지 presign → 스토리지 PUT(200) → complete(200) → 확정 이미지 GET(200, image/png) 통과.
- 설정을 기존 값으로 저장(200), 랭킹 3종(200), 임시 캐릭터 생성(201)·수정(200)·삭제(200) 통과.
- 1장 후보 생성 요청(202), 대기 상태 조회(200), 취소(200)를 확인. 작업 `22149d05-2993-4c78-979b-d033ae454dcb`는 약 90초간 QUEUED 상태로 startedAt이 끝까지 null이었다. 취소 후 임시 캐릭터를 삭제했다. 실제 GPU 결과를 얻지 못했으므로 세트 생성 완료·재생성·인페인팅·버전·다운로드·ZIP의 실파일 검증은 아직 미완료다. 워커의 작업 수신/claim 상태 확인이 필요하다.
- Discord 시작 API는 공식 discord.com/oauth2/authorize로 302 이동. 사용자의 Discord 로그인/동의 후 콜백 전체 과정은 아직 검증하지 못했다. GitHub 계정명은 EmoMix 관리자 로그인이나 Discord 세션을 대신하지 않는다.
- 현재 테스트 계정은 role USER, isCreator false. 관리자 API의 403과 창작자 API의 NOT_CREATOR를 확인. 실제 정산 신청/관리자 심사는 해당 테스트 권한이 필요하다.

`pnpm test:live`는 기본 Node fetch만으로 실제 API 조회 및 예상 권한 제한을 검사한다. 실행 전에 프로세스 환경변수 `EMOMIX_TEST_EMAIL`, `EMOMIX_TEST_PASSWORD`를 설정한다. 기본 대상은 배포 백엔드이며 `EMOMIX_API_ORIGIN`으로 로컬 테스트 서버를 지정할 수 있다. 쿠키/비밀번호는 메모리에만 유지하고 출력하거나 저장하지 않는다. 구매·공개 게시·약관 동의·계정 변경·GPU 생성을 수행하지 않으므로 반복 조회 점검에 사용할 수 있다.

정산을 확인하기 위해 가상의 판매 수익을 운영 DB에 삽입하거나, 검증 성공처럼 보이게 관리자 권한을 올리거나, GPU 결과를 주입하지 않았다. 위 외부 조건을 해결한 다음 나머지 통합 검증을 이어가야 한다.
